Andy Seymour1

Abstract

We present Andy Seymour, a software and data engineer with a first-class MSc in Mathematics and more than ten years of production experience: flight software at BAE Systems, cloud integration UIs at IBM, and data platforms for quantitative sports analysts at Gambit Research. Outside work he builds and runs complete products end to end. Each scrapes messy real-world data, models it and ships it to real users. We show that he can take a problem from raw feed to finished interface without anyone holding the other end of the rope. The proof is constructive.

Keywords: data engineering · React · Python · Spark · Cloudflare · sports data · product

Theorem 1 (Main result). Let P be a problem involving data that is unreliable, late or spread across five sources, and that has to end up in front of people. Then Andy will build the scraper, the model, the API and the interface for P, and keep them running.

Proof. By construction. See §2 for four independent instances and §3 for the professional history that makes them unsurprising.

I started in maths, and I have been building software for a living since 2014. I've written avionics code in Ada for the Typhoon and F‑35, shipped React UIs for IBM's cloud integration products, and led a data team that makes a very large HDFS estate something analysts can actually query.

2Selected works

Four products I designed, built and operate on my own. Each one is live or reproducible, and each is a complete system rather than a demo.

2.1FPL Outlook fploutlook.com

A Fantasy Premier League planner. It shows predicted line-ups and team news, each fixture's xG and clean-sheet probability, expected points and sell prices, plus the cup and European ties worth waiting for before a transfer. A Python pipeline joins the FPL API, RotoWire, FotMob and bookmaker prices. A scheduled GitHub Action refreshes the data and emails an alert on failure. A Cloudflare Worker proxies FPL and handles sign-in.

Python · Next.js · Cloudflare Workers · GitHub Actions · probabilistic modelling

2.2whatslive whatslive.guide

A calendar of UK live sport on TV. Broadcaster listings stop about three weeks out, so whatslive fills the rest in from full season schedules for fourteen football competitions, F1 and MotoGP, marks those fixtures TV TBC, and swaps in the real listing once a channel picks one up. It takes real end times from Sky's EPG (91% coverage of linear events in the next week), and venues and club rosters from other sources. Accounts let you follow teams.

Next.js static export · Cloudflare Workers + D1 · scraping · data reconciliation

2.3TOPIK Trainer topiktrainer.com

A revision site for the reading section of the TOPIK I Korean exam, built on 12 released papers (480 questions). Guests' progress stays in the browser. Signing in with Google syncs it to a D1 database, and each question has a "report a problem" flow protected by Turnstile. The corpus has its own validators, and the app is covered by typechecking, unit tests and Playwright end-to-end tests.

Preact · TypeScript · Vite · Cloudflare Workers + D1 · Playwright

2.4Pre-match odds movement

A research pipeline that takes Betfair Exchange historical data for Premier League match-odds markets and studies how home, draw and away prices move in the 24 hours before kick-off: when moves start, how far they go, and whether they persist or reverse. Signals are tuned on the earliest 60% of matches and tested on the held-out rest, with match-level bootstrap intervals, because signals within one match aren't independent.The honest caveat is in the README. Last-traded-price movement is not an achievable trading profit.

Python · pandas · Streamlit · bootstrap inference · out-of-sample validation
